# ระบบนัดหมายเลสิก / ICL (ฐานข้อมูล Google Sheets ผ่าน Apps Script)

- หน้าเว็บ: ไฟล์ HTML เดียว โฮสต์บน **GitHub Pages**
- ฐานข้อมูล: **Google Sheets** ควบคุมผ่าน **Google Apps Script (GAS)** ซึ่งทำหน้าที่เป็น API
- ล็อกอิน: อีเมล + รหัสผ่านของเจ้าหน้าที่ (เก็บแบบแฮชในชีต `Users`)

> **ห้ามนำข้อมูลผู้ป่วยหรือไฟล์สำรองขึ้น GitHub** repo นี้มีเฉพาะโค้ด

```
public/index.html                    หน้าเว็บทั้งระบบ
apps-script/Code.gs                  โค้ดฝั่งเซิร์ฟเวอร์ (วางใน Apps Script)
apps-script/appsscript.json          (ไม่บังคับ) ตั้งโซนเวลา Asia/Bangkok และสิทธิ์ Web app
.github/workflows/deploy-pages.yml   deploy GitHub Pages อัตโนมัติเมื่อ push เข้า main
```

## ภาพรวมการทำงาน

```
เบราว์เซอร์ (GitHub Pages) --POST JSON--> Apps Script Web app --> Google Sheet
        ^                                   (ตรวจโทเค็นทุกคำขอ)
        └── ตรวจการเปลี่ยนแปลงทุก 15 วินาที (เฉพาะตอนเปิดหน้าจออยู่)
```

## ขั้นตอนติดตั้ง

### ส่วนที่ 1: ฐานข้อมูลและ API (Google)

1. ใช้บัญชี Google **กลางของคลินิก** (เปิด 2-Step Verification) สร้าง Google Sheet ใหม่ ตั้งชื่อ `ฐานข้อมูลนัดหมายเลสิก-ICL`
2. เมนู **Extensions > Apps Script**
3. ลบโค้ดเดิม แล้ววางเนื้อหาจาก `apps-script/Code.gs` กด Save
4. (แนะนำ) Project Settings > ติ๊ก *Show "appsscript.json" manifest file* แล้ววางเนื้อหาจาก `apps-script/appsscript.json` เพื่อตั้งโซนเวลาและสิทธิ์ Web app
5. เลือกฟังก์ชัน `setup` > Run > อนุญาตสิทธิ์ (หน้าจอจะเตือนว่าแอปยังไม่ได้รับการยืนยัน ให้กด *Advanced > Go to ... (unsafe)* เพราะเป็นสคริปต์ของคุณเอง)
6. กลับไปหน้า Google Sheet รีเฟรช จะมีเมนู **ระบบนัดหมาย** > **เพิ่ม / เปลี่ยนรหัสผ่านเจ้าหน้าที่** ใส่อีเมลและรหัสผ่านของเจ้าหน้าที่ทีละคน
7. กลับไป Apps Script: **Deploy > New deployment** > ไอคอนเฟือง เลือก **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)

> เลือก Anyone เพราะเจ้าหน้าที่ล็อกอินด้วยอีเมล/รหัสผ่านของระบบนี้ ไม่ใช่บัญชี Google ทุกคำขอต้องมีโทเค็นที่ผ่านการล็อกอิน คำขอที่ไม่มีโทเค็นจะถูกปฏิเสธ

### ส่วนที่ 2: หน้าเว็บ

1. เปิด `public/index.html` ค้นหา `GAS_URL` แล้วแทนที่ข้อความด้วย Web app URL
2. ขึ้น GitHub

```bash
cd icl-booking-gas
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<USERNAME>/<REPO>.git
git push -u origin main
```

3. Repo > Settings > Pages > Source เลือก **GitHub Actions**
4. รอ Actions ทำงานเสร็จ เว็บอยู่ที่ `https://<USERNAME>.github.io/<REPO>/`

### ส่วนที่ 3: ตั้งค่าเริ่มต้นในระบบ
ล็อกอินแล้วไปแท็บ **ตารางแพทย์** เพิ่มแพทย์และตารางออกตรวจ จากนั้นแท็บ **วันเปิด/ปิดคลินิก** เพิ่มวันหยุด

## การดูแลระบบ

| งาน | วิธีทำ |
|---|---|
| เพิ่มเจ้าหน้าที่ / เปลี่ยนรหัสผ่าน | Google Sheet > เมนู ระบบนัดหมาย > เพิ่ม/เปลี่ยนรหัสผ่านเจ้าหน้าที่ |
| ลบเจ้าหน้าที่ | เมนู ระบบนัดหมาย > ลบเจ้าหน้าที่ (ทุกคนต้องล็อกอินใหม่) |
| อัปเดตโค้ด Apps Script | แก้ `Code.gs` > Deploy > **Manage deployments** > ไอคอนดินสอ > Version: **New version** > Deploy (URL เดิมไม่เปลี่ยน ถ้ากด New deployment จะได้ URL ใหม่ ต้องแก้ `GAS_URL`) |
| อัปเดตหน้าเว็บ | แก้ `public/index.html` แล้ว `git push` |
| สำรองข้อมูล | Google Sheet > File > Make a copy (ทำสัปดาห์ละครั้ง) และดู File > Version history ได้ |
| ดูรายการนัดแบบอ่านง่าย | เปิดชีต `appts` (ดูอย่างเดียว) |

## ข้อควรระวัง

- **ห้ามแก้ชีตด้วยมือ** โดยเฉพาะคอลัมน์ `json` เพราะข้อมูลจริงอยู่ที่นั่น คอลัมน์อื่นเป็นแค่สำเนาไว้อ่าน การแก้ผ่านระบบเท่านั้นจึงปลอดภัย
- **จำกัดการแชร์ Google Sheet** ให้เฉพาะแอดมินที่จำเป็น เพราะใครเปิดชีตได้ก็เห็นข้อมูลผู้ป่วยทั้งหมด รวมถึงแฮชรหัสผ่านในชีต `Users`
- ความเร็ว: แต่ละคำสั่งผ่าน Apps Script ใช้เวลาราว 1-3 วินาที หน้าจอจะแสดงผลทันทีแล้วค่อยยืนยันกับเซิร์ฟเวอร์
- ข้อมูลของคนอื่นจะอัปเดตภายใน 15 วินาที (ปรับได้ที่ `POLL_MS`)
- โควตา: Apps Script มีเวลารันรวมต่อวัน (บัญชีทั่วไป 90 นาที/วัน Workspace 6 ชั่วโมง/วัน) การตรวจทุก 15 วินาทีของเจ้าหน้าที่ 5-10 คนอยู่ในเกณฑ์ปลอดภัย ถ้ามีผู้ใช้มากควรเพิ่ม `POLL_MS`
- ระบบโหลดข้อมูลทั้งหมดทุกครั้งที่มีการเปลี่ยนแปลง หากมีนัดสะสมหลายหมื่นรายการจะช้าลง ควรสำรองและย้ายนัดที่ผ่านไปแล้วออกเป็นรายปี
- ใส่รหัสผิด 5 ครั้งจะถูกล็อกอีเมลนั้น 15 นาที โทเค็นอายุ 12 ชั่วโมง
- ความปลอดภัยโดยรวมเทียบเท่าระบบเล็ก ๆ ไม่ใช่ระดับโรงพยาบาล เพราะผู้ที่เป็นเจ้าของบัญชี Google และ Sheet เข้าถึงข้อมูลได้ทั้งหมด หากต้องการสิทธิ์รายบุคคลหรือบันทึกการเข้าถึง (audit log) ควรใช้ Firebase หรือฐานข้อมูลจริง
- ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหวตาม PDPA ควรปรึกษาผู้เชี่ยวชาญด้านกฎหมายของคลินิกเรื่องความยินยอมและนโยบายเก็บข้อมูล

## แก้ปัญหา

| อาการ | วิธีแก้ |
|---|---|
| หน้าเว็บขึ้น "เชื่อมต่อไม่สำเร็จ" | `GAS_URL` ผิด หรือยังไม่ได้ Deploy เป็น Web app แบบ Anyone |
| ล็อกอินแล้วขึ้น Failed to fetch | URL ผิด หรือ Execute as ไม่ใช่ Me ลองเปิด URL ในเบราว์เซอร์ ควรเห็นข้อความ `ICL booking API is running` |
| อีเมลหรือรหัสผ่านไม่ถูกต้อง | ยังไม่ได้เพิ่มผู้ใช้ในเมนู หรือพิมพ์ผิด (อีเมลไม่สนตัวพิมพ์เล็กใหญ่) |
| ล็อกอินไม่ได้ ขึ้นให้รอ 15 นาที | ใส่รหัสผิดครบ 5 ครั้ง รอ หรือแอดมินตั้งรหัสใหม่ผ่านเมนู |
| แก้ Code.gs แล้วไม่เปลี่ยน | ต้อง Deploy เป็น New version (ดูตารางด้านบน) |
| บันทึกแล้วหายหลังรีเฟรช | เซิร์ฟเวอร์ปฏิเสธ ดูข้อความผิดพลาดที่เด้งขึ้น หรือดู Apps Script > Executions |
| ผู้ใช้สองคนแก้นัดเดียวกันพร้อมกัน | ระบบเก็บฉบับที่บันทึกทีหลังสุด แจ้งกันก่อนแก้นัดเดียวกัน |
